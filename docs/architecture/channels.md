# Channels

Channels 为即时通信应用提供 Terax Agent 入口。首版支持个人微信 iLink 扫码授权和私聊文本，业务代码位于 `src/modules/channels/`。

## 运行归属

仅 `isPrimary && env.kind === "local"` 的永久 Workspace 主窗口启动服务。其他 Workspace 和设置辅助窗口不创建连接运行时。主窗口等待 AI 会话、偏好和凭据初始化，随后读取连接配置。

连接由应用根部 `useChannelsHost` 持有，不随设置页、通知弹层或 AI 侧栏卸载。禁用实例不启动请求或重连 timer；平台适配器与二维码库按需加载。主窗口退出后连接停止，不提供独立后台进程或无头运行模式。

## 分层与多连接

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 连接配置、统一入站消息、检查点和 Adapter 契约 |
| `manager.ts` | 多实例启停、独立接收、有界队列、连接独立执行和恢复状态 |
| `adapters/weixin.ts` | iLink 扫码、验证码、地址校验、长轮询与文本投递 |
| `agentSession.ts` | 固定会话的准备、运行和最终回复投影 |
| `storage.ts` | 白名单配置与单实例检查点 |
| `service.ts` | 主窗口组合入口、登录协调及串行管理操作 |
| `client.ts` | 设置与主窗口之间的定向请求、响应和展示快照 |
| `components/` | 设置管理页、连接状态与通知入口 |

`weixin` 是平台类型，连接 UUID 是账号实例身份。每个实例独占一个 session UUID、接收任务、取消控制器、队列和协议状态。不设置实例数量上限，同一微信账号不能重复注册为两个接收者。

Adapter 把平台输入转换为 `ChannelInbound`，正文、平台消息 ID、对端和回复上下文分别存放。平台令牌和路由信息不进入模型提示词或用户消息正文。

多个连接可以同时接收、重连和执行 Agent，不设跨连接执行锁。每个连接独占执行循环，消息和回复按连接排序。所有连接属于同一用户，默认使用 Local 的 `~/.terax/workspace`，不提供工作目录设置，也不跟随桌面 Explorer 切换。

每个连接的 `busyMessageMode` 在设置页选择，默认 `steer`：运行中输入进入会话运行时的引导队列，与当前任务归并为一次最终回复。`queue` 则等待当前轮及回复发送完成，再在同一会话中开启下一轮，保留上下文。主循环已经关闭接入时到达的消息进入下一轮，不丢弃。前台 Subagent 与普通工具执行完毕后才能接入引导；后台结果与引导共用队列，引导优先且用户输入保持 FIFO。

Channel 只持有传输队列、去重身份和回复上下文，接入后的输入由会话运行时调度。用户中止取消当前轮并清空未消费输入，不发送被中止任务的最终回复；已接受身份仍保留，重连不会重跑这些消息。未消费正文不落盘，异常退出后也不重放。

每连接最多保留十六条在途与待执行消息，达到上限后暂停接收入队，等待现有任务释放容量。该等待可取消，不创建周期性容量轮询。

## 固定会话与执行资源

创建连接时分配并保存 session ID，首次打开或开始使用时准备该会话。重启、断线与同账号重新扫码不会换 session ID。会话使用：

- Local 环境与 `workspace_prepare_default_root` 准备的 `~/.terax/workspace`。
- 主 Agent 快照。
- 全局 `defaultModel`，每轮开始解析并固定，界面临时选中的模型不影响它。
- 完全访问权限，保持现有文件类型、版本、进程归属和灾难性操作保护。

Channel 通过既有 Chat、transport、工具、运行锁和 共享 `runLifecycle.ts` 执行，不修改活动聊天、全局模型选择、权限选择或 Composer 草稿。只有匹配连接在 Local 永久窗口可以提交 Channel 会话。

JSONL metadata 保存不可变的 `channelId`，列表摘要投影该字段。Composer 沿用跨环境会话的禁用机制：环境不匹配或存在 Channel 来源时禁用人工输入与发送，保留输入框和现有布局。

回复在本轮 JSONL 提交并释放运行锁之后投递，只取本轮最后一步的 Assistant 文本。推理、工具输出、Subagent 内部事件和展示记录不会发送到微信。

移除连接先清理协议状态和网络设置，再删除配置引用；清理失败保留连接供重试。协议状态正文被删除，零字节锁文件保留以维持跨进程锁身份。移除连接保留历史会话；绑定仍存在时，普通删除命令拒绝删除，防止配置引用失效。移除配置后可以按原有历史删除流程清理会话。保留下来的 Channel 历史继续禁止人工续写。

## 持久化与失败语义

```text
~/.terax/
  channels/
    config.json
    state/<connection-uuid>.json
  sessions/<session-uuid>.jsonl
```

`config.json` 按连接 ID 保存实例记录，包含名称、类型、固定 session ID、启用状态、运行中消息策略和非秘密账号标识。配置严格校验当前格式，格式错误与磁盘读写错误分开提示；新增前先加载现有配置，加载失败不会写入新连接。协议状态通过 `channels-state:<uuid>` 白名单存储独立保存。调用方不能提供任意文件路径；Rust 校验规范 UUID，复用既有 OS 锁、读取最新值、精确修改和原子替换流程。

配置的账号标识是扫码操作者的微信身份。凭据中的 Bot ID 是平台连接资源；检查点的 `cursorScope` 保存该资源身份。每次启动对照 Adapter 的游标归属，资源变化时只清理旧游标，保留消息身份和固定会话。这也覆盖凭据更新后、配置保存前意外退出的边界。

微信凭据保存在 `app.crynta.terax.channels` service 下、以连接 ID 为 account 的系统密钥条目中，Linux 使用既有 secrets fallback。扫码确认前不替换有效凭据；不能通过重新扫码把已有会话改绑给另一个账号。

检查点只保存同步游标及其归属、最近二百五十六条已接受消息的 ID，以及尚未完成的消息 ID。每条入站身份在排队前提交，游标在本批输入接收后提交，避免重连时重复执行已接受的消息。写入失败立即停止该连接的接收与执行，保留未完成身份，不阻塞其他连接。

待处理消息正文和回复上下文只保留在内存。进程异常退出或连接停止后，不自动重放尚未完成的 Agent 任务。下次连接显示中断提示，需要从微信重新发送。这是首版的恢复边界，不承诺消息或工具副作用的 exactly-once。

会话终态保存失败随具体会话公开，Channel 结束等待并显示存储错误，运行锁与未保存正文仍由既有会话运行时保留。修复存储后重连，下一次请求先补交此前终态，再开始新一轮，不重新执行上一轮 Agent。

投递失败不会重新执行 Agent。微信文本按 Unicode 字符拆分，每片最多一千八百字符，最多八片；超出时引导用户在 Terax 查看完整结果。网络失败只重试当前片段，保持同一客户端消息 ID，最多重试两次。平台已经接收但丢失响应仍属于远端投递的不确定边界。

## 微信协议边界

验证码只有在查询成功后才清除，网络失败保留本次输入自动重试。

扫码使用 `get_bot_qrcode` 与 `get_qrcode_status`，支持扫描确认、平台重定向、验证码及过期反馈。扫码账号的 `ilink_user_id` 是首版允许的私聊对端，不自动接受其他联系人或群聊。

所有 iLink 地址必须为受支持微信域名下的 HTTPS origin，禁止 userinfo、任意端口和跨站地址。HTTP 重定向直接拒绝，登录协议中的地址变化仍须单独校验。每个请求生成新的 `X-WECHAT-UIN`。消息获取使用 HTTP 长轮询，连接或正文读取中断均按实例独立退避，失效凭据要求重新扫码。

每个回复保留原消息的对端及上下文。超过一分钟的任务在发送前尝试通过 `getconfig` 刷新该对端上下文；平台拒绝投递时显示错误，完整结果仍留在会话中。

首版不提供媒体、群聊、联系人路由、远程审批、流式逐段展示或定时主动消息。

## Rust 通用网络能力

`src/lib/http.ts` 是公共 fetch 入口。`http_request` 通过 `started / headers / chunk / end` 事件传递响应，`http_cancel` 按 WebView 与请求 UUID 取消。启动确认解决前端取消早于原生登记的竞争；取消覆盖 DNS、连接、等待响应头与读取正文阶段。

默认请求总超时十五秒、响应上限 2 MiB；调用方可指定一至六十万毫秒的总超时，上限最大 64 MiB。AI 流可以显式省略总超时，由其运行取消控制。原生最多登记一百二十八个请求，窗口销毁会取消其全部请求。

公共 HTTP 按稳定连接身份读取直连或共享代理设置，默认直连且不读取环境代理。微信扫码、轮询和回复使用相同 Channel 身份；模型请求独立遵循所选 Provider 的路由。后续请求读取新设置，在途长轮询不会触发 Agent 重跑。配置与信任边界见 [内置网络与代理](network.md)。

公共 HTTP 同时遵守 Fetch 的 `redirect` 策略：`follow` 在现有安全检查后跳转，`error` 拒绝跳转，`manual` 返回重定向响应。

HTTP 保留协议、地址分类、直连 DNS 固定、重定向和请求头安全检查。全部网络 Provider、模型目录与 Channel 使用同一实现，没有专门的 Rust Channel 网络栈。代理端解析属于显式配置出口的信任边界。

## 设置与状态入口

设置的 Channels 分区与远程页共用轻量双栏布局、列表项、字段及操作区样式，业务数据和保存流程各自管理。左侧按平台平铺实例，只负责选择；右侧直接展示当前实例配置及授权操作。点击添加连接先打开平台选择菜单，当前只展示已支持的个人微信。选择平台后自动生成可编辑的默认名称并进入授权，无需先填写名称；只打开或关闭菜单不会创建实例。平台选项统一声明类型、显示名称和默认命名文案，平台类型通过新增请求显式传递。

名称、运行中消息策略和网络路由使用显式保存，草稿按实例 ID 保留，切换实例和实时快照更新不覆盖未保存输入。名称与消息策略由主窗口在串行管理队列中保存，名称变化不重建接收任务、不取消在途执行或清空队列。启停和授权操作即时提交，切换设置实例不取消主窗口持有的扫码任务。

网络路由继续通过通用 network 设置独立保存，不复制到 Channel 配置。保存跨越两个权威存储，不能视为原子事务；部分失败明确提示并保留草稿，重试只写仍有差异的部分。名称修改不改变连接 UUID、绑定账号或固定会话，也不重写已有聊天标题。

设置辅助窗口只向同进程 Local 主窗口请求管理操作并订阅快照，不直接初始化 Agent 或连接。定向事件权限只授予设置辅助窗口；其他 Workspace 的设置页提供打开 Local 主窗口的入口。

左上角 Agent 通知入口显示连接状态、队列和处理状态，点击打开固定会话。Channel 不重复计入普通 Agent 活动行，完成通知继续复用现有会话通知。

## 扩展与验证

新增平台时扩展连接类型校验、Adapter 创建与平台登录界面。继续复用 Manager、会话和存储，不复制 Agent 循环。需要新的系统能力时，优先扩展通用 Rust 接口；仅支持 Node 的 SDK 不能直接放入 WebView。

回归测试覆盖 HTTP 提前取消、终态事件顺序、跨连接并行、连接内顺序、引导归并和中止清队列、崩溃去重、扫码地址安全、授权对端、分片投递重试和不可变会话来源。真实 Tauri 验证设置与主窗口通信、固定会话输入禁用、HTTP 取消及侧栏关闭后的运行。微信账号登录与远端回包需要真实扫码和私聊联调。

参考项目为本地 NanoClaw 的 Adapter/宿主路由边界和 nanobot 的 Channel/消息队列结构，微信协议以 [腾讯插件](https://github.com/Tencent/openclaw-weixin) 与当前 nanobot iLink 实现为参考。

终端接入与共享生命周期见 [终端 Agent](terminal-agent.md)。
