## 当前任务

目标是在不建立独立数据治理平台的前提下，让 A 股日线同步具备低成本的入库前校验、写后覆盖确认、结构化质量结果和异常标的重试闭环。

- Python 对每个 provider 批次只做一次线性遍历，拒绝非法代码、时间、非有限数值、OHLC 关系、负数成交量和批内重复主键。
- 使用现有同步计划的预期行数识别缺口；写入结束后只读取一次 `bar_overview` 核对本次实际覆盖，不回扫行情分片。
- 每次同步保存一个有界结构化质量快照，异常明细设置固定上限，失败和缺口标的可作为下一次定向同步输入。
- FastAPI 只增加日线同步启动和轻量同步概览；Rust 继续使用通用代理，不解释质量模型。
- 数据页只显示状态、摘要、全量增量同步和异常标的重试，不在浏览器计算质量，也不增加独立质量页面。

完成标准：非法批次不会写入；部分覆盖、写入失败和 overview 不一致都进入结构化结果；用户能从数据页启动同步并对异常标的重试；正常路径只增加线性内存检查和一次主库 overview 读取。

## 当前任务方案

本节是覆盖式临时记录。每次开始新的 Alpha 任务前，必须先用新任务的目标、范围、实施步骤和验证标准完整替换本节，不保留已完成任务方案的历史副本。长期结论和已完成基线同步到长期架构，任务历史由 Git 保存。

长期边界见 [Alpha 综合量化工作站](./alpha-quant-workstation.md) 的“阶段二：数据管理闭环和领域协议”，Python 当前存储与同步基线见 [行情数据与存储](../../alpha/docs/market-data.md)。本节只记录当前最小闭环的执行范围和实际验证结果。

### 目标与范围

- 只修改现有日线 `BarSyncTask`，不泛化为所有数据类型的质量框架。
- 质量 issue 使用稳定、可序列化的小模型，快照只保留有限明细和异常标的集合。
- 定向重试复用同一个同步任务，通过可选 `vt_symbols` 过滤计划，不建立第二套修复任务。
- 前端复用 Alpha 查询缓存、按钮和状态样式，不持久化任务或质量状态。

### 实施步骤

1. 增加纯校验测试，锁定 OHLC、有限数值、非负字段、重复键和批次计划边界。
2. 在同步任务中接入校验、预期行数缺口和一次性 overview 核对，并保存有界质量快照。
3. 增加同步启动与概览 API，锁定并发拒绝、定向标的上限和任务失败状态。
4. 在数据页增加轻量状态区、同步与重试入口，补齐中英文文案和组件测试。
5. 运行 Alpha 相关 pytest、前端类型检查、lint 和测试，审核同步主路径的遍历次数与数据库访问次数。

### 验证标准

- 校验函数不使用 DataFrame 复制、逐行 Pydantic 或额外排序，只遍历标准化字典一次。
- 非法批次整体拒绝，合法但缺少预期交易日的批次允许保存已有数据并标记异常标的。
- 写后核对只读取 `bar_overview`，不为每个证券查询分片。
- 质量快照的明细和重试标的均有固定上限，API 不返回报告文件路径或无界日志。
- 同一时间只运行一个日线同步；服务重启后仍可读取最近质量快照。
- 页面隐藏时停止轮询，运行中禁止重复启动，失败后可以只重试异常标的。

### 执行结果

- 日线 provider 批次现在通过一次字典遍历完成计划边界、有限数值、OHLC、非负数量字段和重复主键校验，同时生成按标的分组与覆盖计数。非法批次整体拒绝，覆盖不足的合法行继续保存并把标的加入定向重试集合。
- 任务只维护每个标的的起止时间和行数，全部写入结束后重建 overview 并额外读取一次主库 `bar_overview`；没有逐证券查询或回扫行情分片。本机 30,000 行、1,000 个标的的纯校验诊断约为 0.08 秒，该测量只用于确认实现量级，不作为跨机器性能门槛。
- 最近质量快照固定保存于 Alpha 状态目录，异常明细最多 100 条、定向重试标的最多 500 个，完整计数单独保留。同步子进程成功或启动后失败都会更新快照，服务重启后仍可读取。
- FastAPI 新增日线同步启动和轻量同步概览，同一时间拒绝第二个日线任务。定向重试通过同一 `BarSyncTask` 的可选标的过滤完成，没有第二套修复任务；Rust 通用代理无需修改。
- 数据页新增一个轻量同步状态区，只展示状态、入库行数、异常数和受影响标的，并提供全量增量同步与异常标的重试。页面隐藏时查询停用，前端不读取报告文件或重新计算质量。
- Alpha 测试为 209 通过、2 跳过；当前量化环境缺少 `pytest-asyncio`，唯一既有异步容器测试改用 `asyncio.run()` 直接执行并通过。完整前端测试为 224 个文件、1146 个测试，`pnpm check-types` 和 `pnpm lint` 通过，lint 只保留仓库既有的 25 个 warning 和 2 个 info。
- 没有执行真实 GM 同步，因为该验证会调用外部供应商并修改用户行情库；provider、子进程入口、API、持久化和 UI 边界均由隔离测试覆盖。
