# Workspace 工作页跨窗口复制

本文描述已经实现的工作页复制能力。目标窗口继续使用现有多进程 Workspace 模型，不是通用辅助窗口。

## 窗口身份

- 每个 Workspace 窗口都是独立应用进程，拥有自己的 WebView、Rust 状态和运行时资源。
- 每个环境只有一个 `Single` 主窗口，使用稳定 ID 和可恢复状态。
- 其他窗口使用 `Extra(UUID)` 临时身份，不加入下次启动恢复列表。
- 从工作页创建新窗口时，源进程预先生成 UUID，新进程必须以该临时身份启动。即使主窗口同时退出，也不能改用 `Single` 身份。

## 运行时交换文件

`~/.terax/workspaces/terax-workspace-runtime.json` 是可丢弃的运行时登记表和消息队列，不是用户配置或窗口恢复文件。它包含：

- `windows`：窗口 ID、环境、主窗口标记、Workspace 锁文件名和启动时间。
- `messages`：目标窗口 ID、环境、创建时间及一次性消息。

所有修改都在专用文件锁内读取最新内容并原子替换。窗口是否存活以现有 Workspace OS 锁为准，不使用心跳。正常退出主动移除登记，异常退出由后续查询清理。损坏或未知版本可以安全重建为空文件，消息十分钟后过期。

该文件也承载已有的窗口激活和打开文件请求，`terax-settings.json` 只保存设置。

## 工作页复制

主窗口可以把白名单工作页复制到同环境的临时窗口：

1. 源窗口把标签转换为不含页面 ID、Space 和运行时资源的稳定描述。
2. Rust 校验页面类型、字段大小、目标环境、临时窗口身份和多窗口设置。
3. 源进程将消息写入目标窗口队列。
4. 目标进程收到文件变化后，在 Workspace 和 Space 初始化完成时原子取走自己的消息。
5. 目标在当前 Space 的活动 Group 中重建页面并获得焦点。

发送到新窗口时，Rust 先写入以新 UUID 为目标的消息，再复用现有进程启动逻辑。立即启动失败会删除该消息。消息采用至多一次消费，不设置确认或回滚协议；失败时源页面始终保留，用户可以重新复制。

## 产品边界

- 只有主窗口提供复制入口，目标只能是同环境的临时窗口。
- 有临时窗口时显示“复制至临时窗口”子菜单和“复制至新的临时窗口”；没有时只显示后者。
- 关闭多窗口模式后显示禁用说明，Rust command 同时拒绝发送。
- 已保存的 Editor、Markdown、Web Preview 和非隐私 Terminal 可以复制。
- Terminal 只在目标创建相同 cwd、模式和自定义标题的新 Shell，不复制进程、输出或前台任务。
- 脏文档、隐私 Terminal、AI Diff 和 Git 临时视图当前不支持。
- 不复制 Space、Group、分割布局、活动状态或页面 ID，不提供移动、拖出、回传和窗口关闭时自动转移。
- 临时窗口仍沿用现有 UUID 状态文件和失效清理机制，但没有稳定恢复身份或额外的持久窗口配置。

通用轻量业务窗口见 [通用辅助窗口](./auxiliary-windows.md)。
