# Workspace 工作页跨窗口交接

本文定义将 Workbench 工作页复制或移动到新窗口的简化方案。新窗口继续复用现有多窗口模型，是同一环境下独立启动的 Workspace 应用进程，不是通用辅助窗口。

## 窗口模型

- 每个环境仍只保留一个可恢复的主窗口状态。
- “复制到新窗口”和“移动到新窗口”使用显式的 `force-new` 启动意图，创建带 UUID 的临时窗口配置，不受“激活已有窗口”偏好影响。
- 临时窗口拥有独立 WebView、Rust 状态和 Workspace 运行时。它不覆盖该环境的主窗口状态，失效配置由现有窗口状态清理机制回收。

## 一次性交接

源进程在 `~/.terax` 写入一次性交接文件，再以交接 ID 启动目标进程。交接文件只保存经过类型白名单验证、可序列化且有版本号的页面描述，不保存 React 状态、DOM、Canvas、控制器或运行时资源。

目标进程应按以下顺序处理：

1. 校验交接 ID、版本、环境、有效期、大小和页面类型。
2. 原子消费交接文件，在当前或默认 Space 和 Group 中重建页面。
3. 写入确认结果。复制成功后源页面保留；移动成功后源进程才关闭原页面。

交接失败、超时或目标进程崩溃时，源页面必须保持不变。交接文件使用 UUID、原子写入、一次消费和过期清理，命令行只传递 ID，不直接传递页面内容。该文件是离散交接载体，不承担窗口之间的实时状态同步。

## 首期边界

- 先提供菜单或命令中的“复制到新窗口”和“移动到新窗口”，始终新建临时 Workspace 窗口。
- 首期不选择已有窗口，不迁移完整 Space、Group、分割布局或活动状态。拖出标签可在后续复用同一交接协议。
- 页面类型按白名单逐类接入。首期只接入能够从稳定描述重建的页面，例如已保存的 Editor、Markdown 和 Web Preview 页面。
- 未保存 Editor、运行中的 Terminal、AI Diff、前台任务及其他依赖源进程内存的页面不进入首期。以后必须先为页面类型定义明确的复制、移动和失败回滚语义。
- 返回主窗口可以在后续使用同一协议实现。关闭临时窗口是否自动返回页面也留到具体交互设计时决定。

## 关键不变量

- 环境在进程启动后不可变，交接不能跨 Local、WSL 或 SSH 环境。
- 移动操作必须以目标确认成功为提交点，不能先删除源页面。
- 页面和路径数据继续经过 Workspace 授权及既有安全校验。
- 临时窗口之间不共享活跃运行时，也不通过共享文件建立持续双向同步。

通用轻量业务窗口见 [通用辅助窗口](./auxiliary-windows.md)。
