# AI 会话与运行规则

## Provider 与模型

Provider 地址、凭据策略、目录与运行 adapter 统一由 `providerRegistry.ts` 定义。消费者使用解析后的连接，不按品牌另拼协议；新增 Provider 优先复用现有协议，仅在现有 OpenAI-compatible 或 OpenRouter 无法覆盖时增加内置项。

模型身份使用完整 `ModelRef`，不从模型名推断 Provider。自定义连接的 ID 不随名称、地址或模型变化。远端目录只发现模型 ID，用户明确添加的模型才进入配置；刷新不自动增删或禁用已添加模型。目录失败仍可手工输入，不保存静态价格、上下文长度或主观能力评分。网络规则见 [内置网络](network.md)。

模型配置可定义带类型的枚举请求参数，路径使用官方 API 命名；已知 SDK 字段由适配层映射，其余扩展保持原名。不按模型名称推断参数能力，不联动或清除关闭思考后的强度选择。模型参数定义按模型独立保存；AI 应用的模型使用配置由 AI 模块统一定义，模型引用与参数覆盖分开精确写入，选值按模块和完整模型身份隔离，避免跨窗口覆盖其他模块或模型。

字符串选项中输入 `null` 表示发送 JSON 空值；“不发送”是用户主动添加的枚举选项，每个参数最多一个，可自定义显示名并设为默认，选中后省略整个参数。两者不能混同。嵌套路径使用点号表示对象层级。

会话选值按当前 Workspace 内的会话和完整模型身份隔离；未覆盖时直接显示模型默认枚举的显示名，菜单只包含已配置枚举。桌面主动选择模型时原子保存完整 Provider、模型身份及该模型的请求参数选择，后续桌面新草稿优先恢复这组最近选择；已有会话继续使用各自保存的参数，Channel 继续使用自身固定模型配置。最近模型失效时依次回退到默认模型和首个可用模型，并清除失效模型的最近参数。新轮发送入口冻结模型及实际参数值，异步准备、工具循环和审批续跑保持快照，界面修改仅用于下一轮。Subagent 与编辑器补全使用各自的参数覆盖，未覆盖时使用模型默认值，不继承父会话选项。Subagent 的跟随模式只跟随父轮模型；运行模型选择与参数编辑模型独立：跟随或指定模型均先确定本轮实际模型，再读取对应覆盖；每次子任务发起时读取并冻结，父轮内后续子任务可使用更新后的配置，跟随模型取父任务实际使用的模型快照。设置中可编辑任意已配置模型的参数，不改变运行选择。补全必须显式选择模型，每次请求冻结独立配置；配置变化不丢弃正在运行的请求结果，结果按原配置缓存，下一次请求使用新配置。缓存不得跨模型或参数配置复用；关闭补全、光标和文档变化仍遵循取消与过期结果规则。显式应用模型失效时保留引用并停止请求，不自动替换模型或改为跟随；重新选择不清除其他模型的选值。

## 模型请求与 Agent 编排

当前有两类执行入口，共用模型使用配置、参数转换和 Provider 适配：

- 直接生成：编辑器补全与提交信息通过文本请求服务执行，目前使用非流式生成。业务模块拥有输入准备、结果校验与任务生命周期。
- Agent 编排：桌面主 Agent、Subagent 和 Channel 通过 Agent 运行时执行，负责工具调用、循环、审批、引导及会话持久化，目前使用流式模型调用。

流式与非流式是模型请求的输出方式，不决定是否需要 Agent。上下文压缩使用独立的一次非流式生成，复用模型配置、参数和 Provider 适配，不创建 Subagent 或工具循环。默认继承当前轮实际模型与参数，压缩模块的显式选值只覆盖对应参数；换模型时使用目标模型默认值及压缩模块覆盖。每次请求冻结配置，显式模型失效则停止，不回退。

直接生成以后需要渐进输出时可增加流式入口，无须创建聊天会话或工具循环；当前文本请求服务尚未提供该能力。Agent 仍保留完整的推理、工具和终态事件，不能用纯文本流替代其执行协议。

直接生成任务创建时冻结模型连接、凭据和实际参数，同一任务的后续请求复用快照与模型实例。输出长度等请求参数完全来自模型定义与模块选值，不额外注入代码中的输出上限；选择“不发送”时保持省略。

提交信息使用独立模型配置，未指定时使用全局默认模型及提交信息模块的参数覆盖。一次生成与至多一次格式修复属于同一任务；暂存区 diff、提示词、结果清洗和校验归 source-control。每个仓库最多运行一个生成任务，互不阻塞桌面 Agent；任务和草稿由业务运行时持有，切换仓库或隐藏面板不会把结果写入其他仓库，生成期间的手工输入不会被晚到结果覆盖。

## Agent 与 cwd

- 内置主智能体用于桌面，Channel 智能体用于即时通讯；两者身份固定、不可删除，可编辑专属提示词、工作区指令文件和工具。配置跨 Workspace 共享，内置字段缺失时使用出厂默认，空提示词与空文件、工具列表是有效覆盖。Custom Agent 保存独立完整定义，新建时预填主智能体出厂提示词。工具逐项选择，编辑工具依赖 read_file；实际 schema 还受入口能力约束，白名单不代替审批策略。
- Agent 只在 draft 中选择，桌面选择器不列出 Channel 智能体。首次发送固定 Agent 身份；首次加载配置并分配进程内版本；保存或共享存储刷新时，实际参与运行的配置变化才更新版本。新轮检查内存版本，未变化时复用提示词与工具。保存成功后对既有会话的下一轮生效，审批续跑、运行中引导和 Subagent 的指令与工具约束保持父轮快照，Subagent 模型配置按子任务独立冻结。
- 主 Agent 与 Subagent 的步骤设置在新轮开始时随运行配置冻结。主 Agent 默认无限，也可设置 8 至 256 的上限；有限模式达到上限后直接暂停并提供继续入口，不再请求收尾。Subagent 使用 8 至 256 的独立上限，达到上限后追加一次阶段性总结，并以未完成终态返回，不能伪装为成功。总结保留工具定义及 toolChoice，在尾部用户消息明确禁止调用工具；移除本地执行器，模型仍返回工具调用时也不执行或续跑。
- 删除 Custom Agent 必须在原生锁内级联删除所有 Workspace 的关联会话。任一会话运行中则拒绝整个操作，通用配置删除不能绕过。
- draft cwd 跟随 Explorer 根；无根时 Local、WSL 延迟准备各自的 `~/.terax/workspace`，SSH 使用 profile 默认根。用户明确打开的其他远端根同样可用。
- 首次发送冻结 cwd，所有相对工具路径基于它解析。恢复会话可恢复已保存 cwd 的授权，但不改变 Explorer 根。
- shell_exec 未显式指定 cwd 时延续该聊天最近同步完成的 Shell cwd；已返回为长任务的进程不得在稍后退出时改变聊天 cwd。
- 终端输出只在明确工具调用时读取，附件和选区只在明确附加时发送，活动标签不自动注入用户消息。

## 提示词与记录

系统提示按通用规则、会话执行环境、工作区指令文件、智能体专属指令、全局自定义指令的顺序组装。内置提示词使用英文；设置页按同一顺序展示可编辑与只读内容，环境和工作区文件只说明运行时加载规则，不推断工作目录或读取文件。Subagent 固定角色段追加在最后并单独展示。

工作区指令文件默认 AGENTS.md，支持英文逗号分隔的工作区内相对文件路径，按顺序去重加载；不支持绝对路径、越界、通配符和文件名中的逗号。文件不存在时静默跳过，其他读取错误中止本轮，不截断正文。配置未变化时复用完整运行配置；首次创建运行上下文、智能体配置版本或全局指令变化时，完整执行提示词初始化，包括重新读取配置的工作区文件，同轮保持原快照。不单独缓存文件正文，不监听或主动汇报工作区文件变化，也不识别用户消息以触发重载；是否调用文件工具由 Agent 根据用户请求判断。磁盘 `systemPrompt` 只用于检查，不能作为恢复输入。

主智能体默认要求真实文件引用采用绝对路径 Markdown 链接，已知文件位置可带 `:行号`。聊天正文与 Subagent 结果在安全过滤前识别文件链接，用户操作时才按当前进程环境查询文件；内部引用标记不写回历史或模型请求。左键点击和右键打开默认使用临时文件标签，并复用行号导航；已有固定标签保持固定。Markdown 保持当前视图并按源码行定位。文件菜单与另存为规则见 [文件传输](file-transfers.md)。

用户附件统一显示在消息气泡上方。图片预览直接复用消息媒体，文本预览按发送时记录的 UTF-16 范围读取正文，不通过标签正则识别文件边界；附件名称、大小、范围及可选来源路径和环境随用户记录保存，不复制附件内容，也不进入模型请求。默认预览与文本另存为使用发送快照，“源文件”菜单操作当前磁盘版本，仅在来源环境与当前进程一致时开放。

本机附件选择、系统文件粘贴和系统拖放均保留绝对路径；WSL、SSH 禁用这些宿主文件入口，文件需先上传至对应环境，再通过文件树附加菜单或 `@` 已打开文件引用附加。`@` 候选仅来自当前应用进程各 Space 已打开的代码和 Markdown 标签，按绝对路径去重并优先保留当前 Space，不扫描工作区；选择后按路径读取当前磁盘内容。用户粘贴时按需读取原生剪贴板文件列表；同一剪贴板同时含文件路径与图片时优先按路径处理，不能在远端降级为内存图片。无文件路径的剪贴板图片仍可在所有环境附加，普通文本保留原生粘贴与撤销。

Composer 仅在本机环境接收落在自身区域内的文件拖放，隐藏或卸载后不接收；本机工作区文件拖入 Composer 只附加，不能继续触发移动文件或打开工作页。系统拖放统一将物理坐标转换为 CSS 坐标后判断接收区。

每个会话只有一份 JSONL，首行 metadata，后续为角色记录；磁盘格式由 Terax 拥有，SDK 适配与模型、展示投影集中在 `lib/conversation.ts`。主 Agent 在 SDK 边界形成的模型历史增量保存为 model 记录：普通步骤保存 responseMessages，审批续跑同时保存 SDK 已生成的审批响应。后续请求与恢复共用这些模型事实，展示由其派生。不重复保存完整请求或原始回复副本，不自行模拟 SDK 的工具参数规范化。模型片段顺序、工具输入输出及 providerOptions 协议元数据原样保留；审批 ID、决定、原因和签名在实时与恢复后保持一致。不向用户正文混入 cwd 或展示属性。尚未形成完整步骤的中止、失败内容仍按已收到的片段保存。

### 缓存前缀不变量

上下文缓存命中是一等公民。所有涉及模型请求的开发和修改，必须优先保持已发送前缀稳定，不能以展示便利或重新拼装历史为由改写模型事实。正常工具循环、内存跨轮、落盘恢复和后台结果接入仅追加新内容；工具定义、顺序和既有消息协议内容保持一致。缓存断点属于请求策略，不写回历史；Subagent 每个工具步骤推进 Anthropic 末尾断点，总结和压缩保留最近请求的断点。

步骤上限、总结和压缩不得删除工具定义或修改 toolChoice；禁止执行通过本地移除执行器实现。压缩摘要请求保留旧前缀，只在尾部追加指令；摘要成功提交后的裁剪才允许改变覆盖范围内的历史。用户明确变更模型、参数、指令或工具配置也可能使缓存失效，这些语义变化不能为缓存而忽略。前缀一致是本项目保证的条件，上游缓存过期、路由与容量仍可能影响实际命中率。

相关变更须在 SDK 请求边界验证前缀一致，并覆盖内存续接、增量落盘恢复、异常工具参数、协议元数据、审批、引导与后台结果、Subagent 循环及总结、压缩请求及提交后的恢复。禁止仅凭缓存百分比或 UI 正文相同判断正确。

- 模型请求前先保存新用户消息和准确的 system prompt。
- 普通流式半成品仅在当前进程，终态再追加完整记录。后台恢复前 checkpoint 完整步骤与内部结果事件。
- 模型请求失败时，终态保存可读且脱敏的运行失败事件，保留已有正文与工具结果。事件在会话中显示实际原因，后续模型上下文明确上一轮未正常完成及工具可能已产生副作用；不伪装为 Assistant 回答。用户取消不记为模型失败，补交终态不重复追加事件。
- 已提交游标仅在原子写入成功后推进；序列化不根据事件标记猜测保存进度。
- 单会话 OS 锁禁止跨进程同时续写。checkpoint 不释放锁，终态提交和原生 release 均成功后才能清除运行锁状态。
- 会话锁文件的打开与删除由一把固定管理锁串行化；删除会话时一并关闭并删除其锁文件。管理锁不覆盖运行期，不阻塞不同会话并行运行。
- 运行与保存订阅由运行时拥有，切换或关闭侧栏不停止工作。保存失败保留运行状态供重试，不能释放未保存内容。
- 只有前台会话挂载消息视图并订阅展示更新。隐藏时卸载消息树和渐进文本；已完成且保存成功的后台 Chat、消息投影与重型缓存立即释放，再次打开从磁盘恢复。运行锁及正在获取运行锁的会话不受展示释放影响。
- 连续正文和推理增量在 SDK 消息复制前定时合并，元数据、片段、工具、审批及终态边界立即冲刷。合并不改变真实文本或协议顺序，取消和上游错误不得丢失已收到的末尾文本。
- 主窗口只恢复仍存在的明确活动会话，其他情况进入 draft；临时窗口从 draft 开始。外部删除或更新不能覆盖本地运行中的会话。

## 会话命令

桌面内置 Agent 与 Channel 共用命令注册、别名、用法和参数入口。只识别输入开头的 `/命令名`；参数原文交给命令解释，路径、普通正文中的斜杠和 `#` 片段不属于命令。未知命令、不支持的参数和附件明确回复错误，不作为模型输入。外部 CLI Agent 保留自身命令语义。

帮助和桌面补全从当前入口可用的注册表生成，中英文跟随应用的 language 设置。命令选择直接填入输入框，每次提交执行一条命令。首次命令沿用会话创建流程确定 Agent 和 cwd，纯回复命令不要求模型配置或加载系统提示。

调用与回执以独立 command 记录追加到同一 JSONL，命令 ID 不等于 Agent turn ID。桌面将两者合并为命令卡；模型投影及后续上下文压缩不读取命令记录。触发 Agent 的命令另行提交正常任务输入，通过结构化关联隐藏重复的任务提示词展示；实际任务输入、工具和 Agent 回答仍进入上下文。任务已提交不代表任务执行完成。

`/compact [instructions]` 使用空闲调度，忙碌时等待当前任务完成；附加说明只用于本次摘要请求，不作为主 Agent 任务输入。调用和回执仍为命令记录，成功检查点单独追加；无可移除内容时不调用模型。

即时命令可以在 Agent 运行期间回复，不能进入用户引导队列或结束当前轮次；需要空闲的命令按接收顺序等待并启动自己的任务，中止当前任务后不再启动剩余等待任务。命令写入由会话运行时协调，借用当前进程的运行锁或在空闲时短暂取得锁，终态释放等待已开始的命令提交。保存失败只补交待保存事实，不重跑命令。历史恢复不自动执行命令，缺少回执时显示结果未确认。

## 用量与上下文

当前用量记录覆盖内置 Agent 会话，包括其 Subagent 与 Channel；补全与提交信息入口目前只返回文本，尚未记录用量，也没有全应用统一汇总。后续接入方向见 [开发方向](../../ROADMAP.md#模型请求观测)。以下规则描述现有会话统计。

内置 Agent 会话的每次模型调用保存独立的 usage 事实，归属 turn、模型及主 Agent 或子任务。压缩调用以独立用途记录，不混入主 Agent 的上下文指示和最终回答统计。标准字段优先使用 SDK 归一化数据；原始 usage 仅在归一化时用于识别 SDK 对缺失字段补零的情况，不整包保存；只保存输入、缓存读取和输出，不采集缓存写入、未缓存输入、文本／推理细分或总 token。未报告的缓存保持未知，仅缺失的输入和可见输出使用字符数乘以 0.8 的本地预估；媒体及不可见推理无法据此计数。

用量沿用会话 JSONL 的 checkpoint 和终态原子提交，保存成功才确认批次。恢复时汇总调用记录，不持久化冗余累计值，也不把 usage 传给模型。旧会话没有调用记录时只预估当前上下文。中止和失败保留已报告的数据，未完成请求标记本地预估。

标题右侧的圆形图表在每次主 Agent 模型调用完成后更新上下文占用比例，无需等待轮末提交；圆形图表与悬浮面板首行的上下文输入均取最后一次主 Agent 调用。面板其余三行累计该会话的全部模型调用，包括主 Agent、Subagent 与压缩请求：缓存输入及加权命中率、未缓存输入和输出；命中率分母是累计输入，不对单次请求比例取平均。任一调用未报告缓存或使用预估输入时，累计缓存细分保持未知，不把缺失值视作零。子任务在任务卡片中保持独立口径：上下文及缓存取末次请求，输出累加该任务的所有调用。切换模型后由新请求更新上下文用量与窗口上限，历史调用记录仍计入会话累计。

每轮最终回答的复制按钮后提供竖向三点统计入口，悬浮或键盘聚焦时以 tooltip 展示本轮输出、该轮末次请求的缓存命中与性能指标，通过 turn ID 查询历史调用。本轮输出累加该轮主 Agent 的所有调用。首 token 延迟取该轮首次可用的 SDK 首次输出时间，生成速度按有效调用的实际输出量与首输出后的耗时加权，工具调用次数按模型返回的完整工具调用计数，不按模型请求数或流式参数片段计数；拒绝或执行失败的调用也计入，中止前尚未形成完整调用的参数不计入。计时随 usage 保存，缺失时不自行补算；子任务与主 Agent 隔离，在“过程”“结果”之后提供“用量统计”标签页，只展示上下文输入、缓存命中、本轮输出和工具调用。

用量缺失时可以估算供展示；只有同模型、同配置且历史前缀匹配，才可用已报告输入作为新增内容估算的基线。持久化的是前缀摘要，不重复保存请求正文。不依据本地估算裁剪消息或拒绝请求。

### 上下文压缩

会话始终保留一份完整 JSONL。成功压缩追加检查点，以真实用户轮次确定覆盖边界；仅模型投影移除覆盖范围内的中间正文、思考、工具调用及结果、后台结果和附件。用户正文、每轮最终回答及历次压缩摘要保留原有顺序，不合并旧摘要，不删除存档或 UI 历史。文本附件复用持久化的范围索引，图片移除媒体 part；无正文的附件消息不产生空模型消息。

摘要检查点在模型中是带固定交接说明的用户消息，在 UI 中是“会话已压缩”提示；识别依靠结构化类型，不匹配用户输入中的文本标记。再次压缩只总结本次新增移除的内容，旧摘要与保留问答作为理解背景。上次检查点之前受到保护的过程，在对应轮次结束后仍可被下一次压缩覆盖。

自动触发参考最近一次主 Agent 请求的输入加输出用量，达到当前模型窗口的 80% 时，在新轮请求前或工具步骤完成后的安全边界检查。运行中的整个用户轮次及其引导、附件和工具配对受保护；审批未完成时不压缩。没有新增可移除内容时不生成摘要。压缩后不检查目标预算、不截断问答、不递归摘要，单轮过大或剩余上下文超限由 Provider 报错停止，用户自行开启新会话。

摘要请求保留当前完整有效上下文、系统提示和工具定义，在尾部追加范围及交接指令。本轮可复用的请求前缀保留缓存断点；更换模型、参数或 Provider 的缓存规则可能影响命中。工具定义没有执行器，摘要请求不进入工具循环；模型仍尝试调用工具、输出为空或输出未完整结束时，本次压缩失败，原上下文保留。

压缩配置在每次摘要请求发起时冻结，默认继承本轮对话的实际模型及参数。同模型只应用压缩用途显式设置的参数覆盖，换模型则使用目标模型的默认参数及压缩用途覆盖。显式选择的模型不可用时明确失败，不静默切回对话模型；独立模型必须能够接收待压缩上下文中的图片等输入。

摘要只发起一次非流式请求，不自动重试。自动压缩失败会中止当前 Agent 轮次并保留原始历史，不能绕过失败继续消费排队输入。手动压缩成功后，上下文指示仍显示最近一次主 Agent 请求的实际用量，直到下一次主请求完成才更新，不用摘要请求用量冒充压缩后占用。

压缩开始结束当前活动卡片，显示复用扫光的“会话压缩中”，不结束活跃 turn。期间不消费引导和后台结果；后台任务可继续运行，结果排队。摘要生成、检查点原子落盘成功后才安装新上下文，再按既有优先级接入排队消息并续跑。空闲手动压缩不额外生成助手回答。

提交前中止会丢弃摘要、停止会话并取消未消费输入，不回滚已执行工具及原有历史；实际调用用量仍保留。已成功提交的检查点不因随后中止而回滚。保存失败保留候选及运行锁，重试只补交，不再次生成摘要；用户取消尚未提交的候选时将其丢弃。

保存失败后的补交只恢复持久化事实，不自动恢复已结束的模型循环或重新执行命令。没有过程、附件等新增可移除内容时，手动压缩也是成功的空操作，不新增检查点。

用户展开、收起工具详情或切换子任务标签时暂停底部跟随，并临时保留当前视口所需的滚动空间，避免内容缩短后卡片标题跳动；回到最新输出时释放保留空间。隐藏标签页不挂载重型内容，也不固定卡片内部高度。

## 工具活动展示

新增或调整工具时，同步定义主会话标题、工具详情和适用的 Subagent 摘要，不依赖工具名回退。活动标题使用“正在……”动作加命令、路径等摘要，动作固定可见，摘要单行省略；参数不足时保留已有标题，无已有标题则暂不展示活动块，有可读摘要即可展示，无需等待完整参数正文。

主会话标题中的命令、路径等文本随同一调用的参数到达立即补全，不重置标题切换计时；不同调用的标题切换保留一秒间隔，期间只保留最新候选。整段活动结束立即显示完成态并取消待展示标题，计时仅控制标题切换。

### 文件改动展示

- 仅采集主 Agent 和内置 Subagent 的 `write_file`、`apply_patch`。Shell、外部 CLI Agent 与其他文件操作不采集，不将工作区或 Git 的全部变化归因给本轮。
- 输入流中的增减行数是预估，展示通道定时合并最新值，中间值可丢弃；成功提交后以原生预备快照修正最终事实，不重新读盘混入其他写入。最终保存等待已经开始的原生修改返回，中止仍保留已完成的编辑。
- 工具行显示单次调用的统计。活动块和 Subagent 卡片收起时，数字绑定实际展示的工具标题；展开后在对应工具行展示，完成标题不保留数字。历史恢复不重播动画。
- 轮末卡片按 `turn_id` 汇总主 Agent 与 Subagent 的净改动，连续编辑合并首尾；基线不连续时保留分段并提示期间存在其他修改。回滚失败只能显示已确认事实及未确认路径，不能把未知状态记为零改动。
- 最终统计与必要的首尾内容作为同一会话 JSONL 的 display 记录保存，checkpoint 只追加未保存批次，不保存预估、动画或展开状态。快照用于历史悬浮预览与整轮只读 Diff，永不进入模型请求，也不提供撤销操作。

## 用户引导

内置 Agent 的用户引导与后台结果由同一接入队列管理。用户输入优先，同类按序；前台工具、wait=true Subagent 和审批仍是接入边界。消费前只显示待接入数量，消费时先保存完整前缀与带 guided 标记的用户记录，再分段展示并请求模型。

运行已关闭接入但终态尚未保存时，新输入等待锁释放后作为下一轮。中止取消所有未消费输入，不恢复草稿或自动重放；已消费历史不回滚。外部 CLI Agent 尚不支持这套运行中引导。

## Subagent

Subagent 只接收通用任务、标签和 wait，使用独立历史并复用父 runtime 的冻结上下文。模型在每次子任务发起时读取当前 Subagent 配置，跟随时使用父轮主模型，再读取对应的独立参数覆盖并冻结整个子任务；超过聊天并发上限立即拒绝，不排队。Subagent 默认步骤上限为 32，可选范围为 8 至 256；主 Agent 默认为无限，输入 0 表示无限，有限值范围同样为 8 至 256。Subagent 的上限后总结只能基于已有上下文和工具结果，必须明确未完成事项，且不计入工具步骤上限。

请求批准模式只允许父白名单中的只读工具，没有独立审批通道，需要提升时返回拒绝；完全访问继承父白名单。两者均移除 run_subagent，禁止递归委派。

- wait=true：结果作为原 tool result 返回。
- wait=false：先返回 started，完成结果追加为同一 turn 的内部 event。模型投影为标准 user 消息，UI 归属工具卡片，不改写既有 tool result 或历史前缀。
- 模型到达候选终态但仍有后台任务时保持运行锁；等待结果或引导后继续完整循环，直到无待处理工作。
- 专用卡片只显示模型调用状态、工具摘要和终态，不流式展示子任务推理或中间正文。标题动作至少显示一秒，计时只影响展示。
- 运行过程及 SDK 完整模型历史在内存，含总结请求在内始终保留协议元数据。子任务结束后不恢复模型调用，因此只保存终态 display 快照，不持久化独立模型历史或协议元数据；不重复 task、结果正文或完整工具输出。崩溃不保证恢复详细过程；损坏或无对应调用的展示记录忽略。
- display 记录和内部展示 data part 永不进入模型请求。
