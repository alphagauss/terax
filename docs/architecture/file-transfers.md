# 文件传输

文件传输在 Host 与当前进程绑定的 WSL 或 SSH 环境之间执行，由 Rust 拥有任务、调度与提交。历史使用 `~/.terax/transfers` 下的任务 Journal；重启将中断任务标为失败，不提供字节级续传。

文件管理器的系统文件粘贴与拖放共用导入流程：本机复制，WSL 与 SSH 使用 Direct 后台上传。粘贴目标与顶部新建文件、文件夹按钮一致：选中目录用该目录，选中文件用其父目录，无有效选择用当前根目录；操作触发后固定目标，不随后续选择改变。仅导入剪贴板中的真实文件路径，纯内存图片不生成文件。

## 策略与冲突

Direct 和 Archive 由用户显式选择，共享规划、目标预留、staging、冲突和提交规则，不自动切换或降级。

聊天文件引用、文件树与搜索结果共用文件菜单。“另存为”导出磁盘版本到本机：本机文件原子复制，WSL 与 SSH 单文件使用 Direct 下载并保留用户选择的目标名，沿用后台任务、冲突和重试规则。目录不提供另存为。系统打开方式与文件管理器显示只对本机环境开放。

- Direct 逐文件复制。可恢复失败在同一目录任务中重试或忽略；连接中断、空间不足、Journal 或提交失败终止任务。重试重新验证源与冲突，不沿用旧批量决定。
- Archive 以 tar.gz 传输，按可信 manifest 验证和解压；缺少所需远端工具明确失败。source-first 合并优先源冲突项，destination-first 保留目标冲突项，两者保留不冲突条目。
- 目标已存在时必须取得绑定到当前任务与目标状态的冲突决定。新目标 no-replace 发布，不能覆盖并发创建的文件。
- 传输前后同路径都为目录时，原位协调条目，不能替换目录身份，以保留终端 cwd、句柄和 watcher。最终删除目录或改成文件不受此限制。
- Direct 已成功提交的 root 在后续失败时保留；Archive 多 root 提交失败尝试整体回滚。原位目录修改逐项可见，不承诺整棵目录瞬时切换。

### Archive 提交性能取舍

大量小文件覆盖时，逐条启动外部命令会放大进程创建和文件系统元数据处理成本，导致归档字节传完后仍长时间等待提交。优化以减少命令调用为主，遵守上述目录身份和回滚约束。

SSH、WSL 上传继续在目标侧使用 Bash：同层普通文件有界批量移动，父目录队列跨子目录递归保留；合并属性查询，跳过重复加权限，批量恢复相同属性，最终权限仍按子目录到父目录恢复。批次部分成功时逐项登记实际移动，失败按记录反向恢复。该方案沿用现有工具依赖，不增加 Python 或远端服务；仍承担逐项检查和文件系统操作成本，暂不引入并行提交或跨目录预扫描，以控制并发和恢复逻辑的复杂度。

## 目录内容同步

SSH、WSL 文件夹和当前目录菜单提供“同步文件夹内容”。本机目录与环境目录直接对应，递归同步内容，不额外嵌套来源目录名。用户选择单向上传或下载；只复制目标缺失的条目和源端修改时间严格更晚的文件。时间统一按秒比较，相等或目标较新时跳过，不按内容摘要判断差异。两端时钟影响判断，同秒修改可能跳过；同名文件整体覆盖，不合并代码。

同步保留目标独有条目，不传播删除或识别重命名。默认勾选遵循源端 `.gitignore` 和排除所有层级的 `.git` 文件、目录；依赖与构建目录可单独勾选，只排除任意层级的同名目录，保留同名文件。其他名称以标签逐项添加，精确匹配所有层级的文件和目录，不解释通配符。

忽略规则只读取所选源目录及子目录的 `.gitignore`，支持根路径、目录规则和 `!` 例外，不要求 Git 仓库，也不读取目标端、上级目录或机器全局规则。已跟踪文件同样按规则过滤，显式名称排除优先；排除 `.gitignore` 文件自身不停止应用其规则。固定名称排除在扫描时剪枝，目录自身的类型仍保留供目标冲突检查；源端 `.gitignore` 和元数据批量收集后使用同一 Rust 解析器过滤，不产生逐文件 SSH 请求，不额外依赖远端 Git。类型冲突、链接和特殊来源条目在预览中标出，需要处理或排除后执行。修改排除选项后重新预览；预览仅显示有界明细，统计覆盖过滤后的清单；执行重新比较两端，不把预览当作永久覆盖授权。

同步明确使用差异 Archive：SSH 或 WSL 一次脚本扫描目录元数据，仅将选中的文件及必要目录打包；下载通过 NUL 清单和非递归 tar 保持传输范围，打包前后批量复验来源。沿用任务、取消、Journal、staging 和事务提交，目标端提交时再次比较时间，保留已经变得更新或同秒的目标。已有目录原位协调并保留其属性；运行中出现类型冲突则失败并按既有规则回滚。脚本通过标准输入发送，清单大小、扫描条目和执行耗时有界。远端同步需要 Bash、GNU find/stat 及现有归档工具，缺失时明确失败。

每个环境目录在当前 Workspace 状态中保留最近一次完整成功同步的本机目录、方向和排除设置；不同环境及窗口沿用现有存储隔离，临时窗口由统一启动清理处理。打开相同规范路径时恢复设置，仍需重新预览。重置只恢复当前表单默认值，关闭或预览不修改记录；只有后台任务完整成功并保存终态后才更新设置，失败、取消和带错误完成不覆盖。配置来自实际执行的请求，不依赖对话框挂载；同一路径最后成功完成的任务覆盖旧设置。清理或裁剪传输历史不移除同步配置，设置保存失败单独提示，不改变已成功的传输结果。

## 安全与清理

规划使用绝对规范路径，拒绝 traversal、控制字符、链接和特殊文件。Explorer 明确选择可位于 profile 默认根外；目标预留检查祖先与后代重叠。提交前重新检查源 identity、大小和冲突前提。

Archive 拒绝绝对或越界路径、重复和意外条目、大小不符、无效压缩及过量尾随数据，不能用压缩包中的路径代替 manifest 授权。

staging 与 backup 清理必须属于精确任务及目标父目录，不能删除最终目标。临时目录权限修复仅限其自有树，不跟随符号链接、不跨挂载、不提权。

破坏性提交前保存 recovery 票据；只有确认提交成功后才可标为 disposable 并自动清理 backup。重启只清理已持久化 disposable 的精确路径，recovery backup 保留供恢复，不扫描 Workspace。

SSH 中断后清理只能等待相同 host、port、username 的 endpoint；profile 改绑不能转移授权。I/O 与重试均有时限，仍有清理所有权的历史不得移除或裁剪。突然退出遗留的 staging 不当作已完成目标或复用。

## 状态与资源

传输面板在预检结束后自动展示进度，保留当前输入焦点；用户主动打开或进入面板后，才按普通弹层处理焦点进入与恢复。

Rust 快照是任务权威，前端本地化稳定错误码，不解析诊断文本。整任务重试创建新任务；Direct 文件重试创建新的执行身份与 staging。

字节进度不代表整任务完成。字节传完后，UI 切换为校验、解包或提交的阶段文字与运行指示，隐藏满格字节进度和传输速度；不估算提交百分比或引入逐项实时进度协议。提交脚本不可暂停，该阶段不提供暂停入口。

排队暂停和等待冲突不占传输许可，取消唤醒等待者。任务、历史、输入和 I/O 均有界，具体限制以实现为准；SSH 传输 session 不与 Explorer 读取缓存共用。

验证真实 WSL、SSH 传输时使用 Tauri 进程，覆盖方向、冲突、取消、中断和恢复，并跨边界比较内容。一般检查见 [测试指南](../contributing/testing.md)。

Archive 在桌面原生日志中保留粗粒度性能汇总，标记为 `TERAX_TRANSFER_PERF`，按 `task` 关联。记录打包、传输、校验解包、提交（含清理）和整任务的本机耗时，以及归档大小、文件数与执行结果。不向远端插入计时命令，不额外扫描或逐文件打印。阶段耗时可能嵌套，不能直接相加；`event=exit` 仅代表计时作用域退出，成功与否以任务结果为准，暂停也计入耗时。日志位置见 [运行时调试](../contributing/ui-runtime-debugging.md)。
