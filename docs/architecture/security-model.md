# 内置 Agent 安全模型

本文件定义内置 Agent 的授权与原生执行边界。外部 CLI Agent 的权限见 [独立协议](external-agent-runtime.md)，HTTP 地址与代理策略见 [网络规则](network.md)。

## 权限模式

| 操作 | 请求批准模式 | 完全访问模式 |
| --- | --- | --- |
| cwd 内非敏感读取、搜索、写入和普通结构操作 | 自动执行 | 自动执行 |
| cwd 外、敏感路径、目录递归删除 | 整个 tool call 一次性批准 | 自动执行 |
| 可明确分类为 cwd 内的普通开发命令 | 自动执行 | 自动执行 |
| Shell 外部路径、网络或不透明命令 | 一次性批准 | 自动执行 |
| 已配置服务的 web_search、web_fetch | 自动执行 | 自动执行 |

网络工具只访问用户选择的服务 API，查询或网址发送给该服务，抓取由服务端执行，不访问本机文件或继承 Workspace 私网授权。它们仍受智能体白名单约束，请求批准模式的 Subagent 可继承父白名单中的这两项只读能力。

批准只提升原调用，不修改会话 cwd 或后续权限。两种模式都保留普通文件、大小、版本、进程归属和灾难性操作保护。Shell 字符串分类是保守的审批判断，不是进程沙箱。

桌面会记住最近一次权限选择并用于后续桌面会话。Channel 没有交互式审批通道，固定使用完全访问模式，不读取或修改桌面选择。

`shell_process` 的 stdin 写入在请求批准模式下需要批准，完全访问模式自动执行；poll、EOF、终止与列表自动执行，但只能操作当前聊天登记的普通 Shell 进程。

拒绝以独立的 `output-denied` 结果返回并持久化，不能伪装成执行错误；模型不得换工具、路径、编码或 Shell 绕过同一次拒绝。

## 文件边界

六个模型文件工具统一进入 `terax-core` 的文件授权服务，将 owner 绑定到固定 cwd 与环境。请求批准模式的未提升调用限制在会话根内，并过滤敏感路径；完全访问和一次性批准解除这两项上界。

- 读取和写入同时检查字面路径、canonical 路径与普通文件类型；不存在的目标解析最近存在祖先，I/O 使用授权后的稳定物理路径。敏感类别以源码策略为准，发现和宽泛搜索不能泄露被过滤结果。
- Windows Local 拒绝设备名和 alternate data stream；WSL、SSH 保持各自路径大小写语义。移动或删除最终符号链接只操作链接本身。
- `write_file` 必须显式选择 create 或 rewrite，并创建父目录。create 要求目标仍缺失；rewrite 和 `apply_patch` 要求当前聊天通过 `read_file` 或成功的 `write_file`、`apply_patch` 建立当前版本基线。局部读取可以建立基线，搜索和 Shell 输出不能。全文替换前智能体须了解完整当前内容，局部读取用于定向补丁。目标内容已知且文件未被外部修改时，无须重复读取。批量补丁在路径授权后一次报告全部缺失基线的文件，此时不写入任何文件。
- 精确补丁仅处理已有的 UTF-8 文件，并保留原 CRLF 换行风格。同一文件的替换按输入顺序处理；匹配数量约束失败时整批不写入。相近片段和差异仅用于错误诊断，不参与自动匹配或修正替换正文。
- 自动写入和需审批写入都经过 prepared mutation 与条件提交。需要审批时先生成不可变 before/after，在一个或多个只读 diff 页按整个调用决定，批准前不得写入。
- 提交前重验路径和全部基线，再逐文件原子发布；中途失败尽力回滚，不承诺跨文件系统事务。结构操作拒绝隐式覆盖、文件系统根和未显式声明的目录递归删除。

普通 PTY、Git 等 Workspace 功能继续通过工作区授权 registry，不能借用模型的一次性提升绕过自身边界。

## 进程与远端任务

Agent 短命令和长任务使用同一 owner 隔离的原生进程表，输出与容量有界。超时、取消、聊天删除和应用退出清理受管进程树：Local 使用 process group 或 Job Object，Windows 在恢复执行前加入 Job Object；WSL、SSH 使用远端进程组。应用退出先关闭新进程准入，再有界等待本应用进程内的清理，不影响其他 Workspace 窗口。SSH 受管进程可能随连接中断，断线后不承诺仍在运行或已成功清理。

独立非交互服务由用户管理，不持久化到会话进程表，也不提供 `shell_process` 控制。Linux、macOS、WSL 和 Linux SSH 可用 `nohup ./server </dev/null >server.log 2>&1 & echo $!` 启动；普通 Shell 正常结束后释放 POSIX 后代归属，WSL 与 SSH 清理只回收正常结束的启动登记。必须重定向全部标准流，否则后代持有的管道仍会占用受管执行。Windows 本机普通 `Start-Process`、`Start-Job` 仍受 Job Object 约束，独立启动使用系统 WMI/CIM `Win32_Process.Create`，设置工作目录、隐藏窗口的启动参数及输入输出重定向，并检查返回码和 OS PID。外部 CLI Agent 保留原有的退出进程树清理。

启动命令退出不代表服务已经就绪，Agent 须另行核对实际 PID 与服务状态，并交代日志及停止方式。启动命令正常结束后，独立服务不受原调用的超时、会话取消和应用退出清理；应用不扫描或自动接管这些服务。正在运行的受管启动命令仍遵循原有取消与清理规则，不按命令是否包含 `nohup`、`&` 等文本判断豁免。

子任务仍使用父会话的授权身份，进程另按任务与执行批次标记归属。取消先关闭原生执行准入，再终止进程树；已开始但尚未登记的启动也必须纳入清理。正常结束执行只释放准入，正常保留的受管后台进程仍可按任务或整个会话停止。普通停止仅关闭活跃执行的准入并清理其进程树，已结束执行的进程不受影响；清理失败时保留已关闭的执行登记以便重试。显式全会话清理在会话锁内执行，仍覆盖已结束任务与历史执行的资源。

封闭 SSH Bash 任务只实现原生枚举操作，参数转义、正文走 stdin，不上传脚本或开放端口。写入响应丢失后先核对预期与替换版本，不能盲目再次提交。能力探测不扫描 Workspace、不自动安装远端依赖，失败不解除文件权限检查。

## 秘密

模型和连接凭据使用系统密钥链；Linux 使用既有受限权限 secrets 文件。秘密不进入普通配置、localStorage、会话正文或日志。
