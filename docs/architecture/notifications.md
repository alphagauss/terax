# 桌面通知

系统通知由当前 Workspace 进程的原生服务统一发送，主窗口、辅助窗口和业务模块共用封闭目标协议。调用方只提供标题、正文及目标，不提供进程 ID、窗口 label、URL 或可执行命令。

## 身份与导航

- 主窗口目标按模块解析为 Workspace、终端标签或 AI 会话。前端通过现有业务入口导航，目标已删除时只保留原生窗口激活，不创建替代任务。
- 辅助窗口目标复用辅助窗口打开协议和注册表；测试通知定位到设置的常规分区。
- 通知点击只在发送它的进程内解析。系统仅回传不透明身份，原生目标表有容量和有效期限制，不持久化通知正文或目标，也不在进程退出后重启 Workspace。
- 主窗口先订阅再读取待处理目标，处理后按通知身份确认，旧确认不能清除较新的点击。窗口重挂载不丢弃尚未确认的目标。
- 点击通知主体激活目标；系统关闭、过期和清除通知不改变任务、审批或应用内关注状态。

## 平台

Windows 使用 Terax 的 AppUserModelID，在每个进程首次发送时初始化当前用户的显示名称和图标；并发发送共享初始化结果，成功后不重复访问图标文件或注册表，失败后允许重试。开发构建不再借用 PowerShell 身份。Linux 使用桌面通知服务的默认动作。macOS 使用 UNUserNotificationCenter，需要具有 bundle 标识并签名的应用，未满足条件时明确返回错误。

原生发送接口等待操作系统 API 返回，失败原因传回调用方；成功只表示请求已接受，不能证明通知已显示。系统通知权限、勿扰模式和桌面环境策略仍由操作系统决定。通知响应观察器有数量及时间上限，不占用每条通知一个长期阻塞线程。

## 提醒开关与测试

智能体提醒总开关仅控制系统通知和应用内弹出提示，后台通知仍可在铃铛查看；各 CLI 的 Hook 安装状态独立管理。业务通知按窗口焦点和当前页面决定投递方式。

设置中的测试先准备权限，再等待两秒直接发送系统通知，不经过业务可见性抑制，也不验证 CLI Hook。关闭提醒或离开设置取消尚未发送的测试。测试结果区分权限拒绝、请求已接受及具体失败原因。
