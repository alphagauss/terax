# 通用辅助窗口

本文定义供业务模块复用的轻量原生辅助窗口。它与设置窗口类似，运行在当前 Terax 进程内的独立 WebView 中，但不承载完整 Workbench，也不用于移动标签页。

## 公共能力

辅助窗口基础设施只负责：

- 创建、显示、聚焦和关闭 `WebviewWindow`，并校验窗口类型与实例标识。
- 提供统一的标题、最小化、最大化和关闭操作。macOS 使用原生窗口控制按钮，Windows 和 Linux 使用 Terax 窗口控件。
- 加载全局样式、主题、语言、字体、错误边界和必要的窗口生命周期逻辑。
- 在未打开辅助窗口时不加载业务页面，也不建立额外连接、定时器或观察器。

具体业务通过受控的窗口类型注册自己的页面，并决定页面内容、初始参数、数据来源、交互、状态和持久化方式。公共层不接受任意 React 节点，也不定义通用业务状态协议。

## 边界

- 每个辅助窗口拥有独立的 React Root 和 JavaScript 上下文，不能直接复用主窗口中的 React 状态、DOM、Canvas 或控制器。
- 主题和语言等全局设置复用白名单共享设置；业务数据通过已有 Rust command、服务 API 或该业务明确设计的事件同步。
- 辅助窗口默认不提供标签栏、Sidebar、状态栏、Space、Group 或 Workbench 页面恢复。
- 辅助窗口不能拥有 Workspace 级 PTY、LSP、Shell、文件监听、SSH 或 AI 运行时，也不能扩大当前进程的授权范围。
- 是否单例、是否记忆尺寸和关闭时如何处理业务状态，由具体窗口类型声明。

适合该能力的场景是简单状态窗口、监控视图和按需独立展示的业务组件，例如轻量行情或任务状态视图。完整工作页进入新窗口时使用 [Workspace 工作页跨窗口交接](./workspace-page-handoff.md)。

## 实施顺序

首期只实现公共窗口外壳、受控页面注册以及主题和语言同步，再选择一个低状态复杂度的业务页面验证。只有业务明确需要时，才增加该类型专用的通信或恢复能力。
